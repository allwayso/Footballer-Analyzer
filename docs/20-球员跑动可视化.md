# 球员跑动可视化

独立 HTML 数据探索页，复用已完成人工身份绑定、已确认球场标定的运行。包括逐源帧球场回放、最近三秒轨迹、个人整段轨迹、时间加权活动热图、逐秒平均速度和跑动对比；可按身份名称分组、点选球员、排序和导出 CSV / JSON / 热图 PNG / 离线页面。不占用原视频页面或人工校验页，也不启动新端口。

```powershell
$env:PYTHONPATH = (Resolve-Path .\src).Path
& D:/FootballerAnalyzer/.venv/Scripts/python.exe scripts/visualize_player_motion.py --run D:/FootballerAnalyzer/outputs/run_20261020T110206_ca1f3de5
```

输出在该运行的 `reports/report_viz_<版本>/`，通过**现有服务**的 `/reports/<运行>/<版本>/report.html` 打开，或直接打开本地 `report.html`。此文件内嵌全部图表数据，不依赖外网。目录不写正式跑动报告的 `manifest.json`，不会替换原报告或成为原页面的“最新报告”。

统计采用现有投影、切段与 One-Euro 平滑规则；缺帧、无效投影、绑定边界和超速跳变均断段，不跨轨迹编号补距离。热图将连续时间边按秒计入终点网格（35×23），所有人物共用色标；速度分箱按时间边与一秒窗口的真实交集加权。距离和平均速度应结合有效时间和覆盖率阅读，不外推整场。

仅在可视化副本内采用仍生效、且有唯一显式身份的融合组：未绑定片段可继承该身份；不同身份冲突的组不继承；原显式绑定和排除保持优先。同人物同帧最多一条观测，先取显式绑定，再取置信度较高者。保留继承、重复观测和无法继承组的明细，不改写 `tracks.parquet`、`bindings.yaml` 或 `field_review.json`。

保存 `input_snapshot.json`、`data.json`、`diagnostics.json`、`summary.csv`。快照含原清单、轨迹摘要、完整逐帧标定、绑定、人物档案及融合历史；计算期间输入变化会拒绝导出。导出页面是静态快照，之后修改标注需重新生成。

首份素材：`barca_girona_25m00s` / `run_20261020T110206_ca1f3de5`，源帧 `[0,1503)`，25 fps，60.12 秒。20 个绑定身份中包括19名球员与1名裁判。原球队字段均为 `home`，因此仅按人工填写的 `barca_`、`girona_`、`referee_` 身份前缀组织显示，保留原标签，不推断进攻方向或球衣号码。有效手动融合将轨迹36并入 `barca_10`，本页已纳入该副本身份。

米制数据沿用用户确认的标定；未通过独立实测路程的精度验收。可见画面与有效区域只覆盖部分人物，不能据此推断完整阵容或整场跑动。
